# Formato BLE y pestañas de Gestión técnica

La pantalla agrupa las utilidades en General, Bluetooth y formato, MQTT, Diagnóstico B5 e Historial. Cambiar de pestaña no solicita lecturas ni envía comandos. Abrir Gestión técnica conserva el comportamiento previo: puede solicitar 2030 si está habilitado. Las pestañas admiten flechas, Inicio y Fin; en pantallas pequeñas se desplazan horizontalmente.

`2059` consulta `timestamp` y `adv_data` para MKGW3 V2. `2065` consulta los 12 interruptores de interpretación especificados en el protocolo V2. Los objetos se validan estrictamente y sus valores se presentan como observados, sin afirmar correlación inequívoca ni estado actual. Una respuesta con campos faltantes, adicionales o no numéricos se rechaza; no se completan valores por defecto. El manual indica que `parse_adv_data` se eliminó de `1059` en V2 y que la interpretación por tipo se controla con `1065`.

Las respuestas válidas rellenan casillas separadas: `1059` envía los dos valores de datos reportados y `1065` los doce de interpretación. Los valores marcados se solicitan activos y los desmarcados inactivos; el operador revisa el conjunto completo antes de confirmar. Desactivar datos crudos o tipos de interpretación puede afectar detecciones y diagnósticos. Ninguna de estas acciones toca filtros B5 1053, intervalo 1063, comandos físicos, MQTT de conexión ni alarmas. Si todos los valores coinciden con la observación, no se publica.

La API exige técnico autorizado, compañía, gateway activa, identidad MKGW3 V2 verificada, lectura reciente del mismo usuario y confirmación explícita en la interfaz. Bajo el bloqueo compartido comprueba la observación y el diario; una lectura más reciente, un comando del mismo tipo posterior, un dato ausente o una lectura de más de 60 segundos obliga a consultar de nuevo. La reserva durable de `017` impide reutilizar una lectura después de intentar publicar, incluso ante error incierto. No se hacen reintentos automáticos. El ACK no demuestra el estado actual: consultar de nuevo para observarlo.

La observación y el diario se guardan en transacciones distintas y pueden tener fechas diferentes. Se acepta la observación si su fecha cae entre la creación y el registro de respuesta y sus datos coinciden; no se exige igualdad exacta de timestamps. Esto corrige también la comprobación preexistente de 2053. No existe correlación inequívoca ni compare-and-swap en el protocolo: respuestas tardías o cambios externos pueden dejar obsoletos los valores entre lectura y escritura. El operador debe valorar este riesgo y observar la respuesta posterior; no se afirma conservación absoluta del estado físico.

El reintento manual y confirmado de `2030` puede superar un timeout histórico sin borrar el diario, pero la respuesta podría pertenecer a un intento anterior. Lecturas pendientes, publicadas o con error de publicación siguen bloqueadas; no hay reintentos automáticos tras un resultado incierto.

## Compatibilidad de recursos y sesiones abiertas

HTML y JavaScript comparten el contrato `20261126-2`; debe cambiarse en conjunto con el backend si cambia el contrato de escritura. Las URLs del JavaScript y CSS usan la revisión de caché `20261126-3` para servir el catálogo completo de casillas, incluidas las opciones observadas con valor cero. El JavaScript rechaza un HTML sin el contrato esperado y solicita recarga antes de inicializar la pantalla. El servidor rechaza el contrato antiguo de escritura de formato y cualquier petición sin el identificador esperado: una sesión vieja debe recargar para volver a solicitar 1059/1065. Esto no bloquea operaciones históricas de otros endpoints ni constituye una medida de autenticación.

En despliegue, publicar primero el backend que rechaza el contrato anterior; después publicar los recursos correctos y finalmente el HTML. Validar a través de Nginx las tres respuestas, cabeceras de caché y versiones, y conservar los archivos anteriores para retorno coordinado con el backend. El HTML debe revalidarse; el parámetro de versión no garantiza el comportamiento de un intermediario que ignore la cadena de consulta. Una pestaña ya abierta mantiene su JavaScript hasta recargar y puede necesitar una recarga explícita. Abrir Gestión técnica puede iniciar 2030: no usarla para la comprobación pasiva.

La migración `017_gateway_ble_report_options.sql` extiende validaciones sin modificar migraciones anteriores y crea la tabla de reservas. Antes de un despliegue, revisar secuencia, ledger, compatibilidad y backup en una copia aislada; no restaurar un backup sobre datos nuevos. Para retornar, volver a la imagen anterior sin eliminar la tabla ni modificar filas históricas; antes de una reversión SQL adicional verificar que ninguna versión nueva la necesita y revisar referencias y datos. La verificación física y la correspondencia de los campos parseados con la doble pulsación permanecen pendientes de autorización y prueba en staging.
